# 표시하고 다시 순회해 누락 값 찾기

> 상태: 오늘의 학습 자료 및 연습 과제

## 언제 사용하는가

가능한 값의 범위를 알고 있고, 입력에 등장하지 않은 값을 찾아야 할 때 사용한다. 입력을 받으며 등장 여부를 표시한 뒤 전체 범위를 다시 순회하는 방식이다.

## 두 번의 순회가 하는 일

예를 들어 1부터 5까지 중 입력이 2, 3, 5라면, 첫 순회에서 exists[2], exists[3], exists[5]를 true로 표시한다. 다음 순회에서 false인 1과 4를 찾는다.

첫 번째 순회는 입력을 상태로 바꾸고, 두 번째 순회는 그 상태를 해석한다.

## 경계와 인덱스

값의 범위가 1부터 30이라면 배열을 31칸으로 만들면 값과 인덱스를 그대로 대응할 수 있다. 이때 인덱스 0은 사용하지 않는 칸이다.

메모리를 한 칸 아끼려고 value - 1을 인덱스로 사용할 수도 있지만, 초보 단계에서는 변환 과정에서 실수할 가능성이 커진다. 범위가 작다면 읽기 쉬운 대응을 우선해도 좋다.

## 정렬이 필요 없는 이유

결과 탐색을 작은 인덱스부터 시작하면 누락 값도 자동으로 오름차순으로 나온다. 입력 순서는 결과 순서에 영향을 주지 않는다.

## 핵심 질문

1. 입력 순서가 섞여 있어도 결과가 오름차순으로 나오는 이유는 무엇인가?
2. 길이가 30인 배열을 쓴다면 학생 번호를 어떤 인덱스로 바꿔야 하는가?
3. 가능한 번호가 1부터 10억까지라면 이 배열 방식이 부적절한 이유는 무엇인가?

## 직접 연습

1. 1부터 10까지 중 등장하지 않은 수를 모두 출력한다.
2. 알파벳 소문자 중 문자열에 등장하지 않은 문자를 출력한다.
3. 같은 문제를 HashSet의 contains로 다시 작성한다.

## 복습 체크

- [ ] 입력 표시와 결과 탐색의 역할을 구분해 설명한다.
- [ ] 시작·끝 인덱스를 종이에 먼저 적는다.
- [ ] 모두 등장한 경우에도 불필요한 출력이 없는지 확인한다.
- [ ] 배열 방식과 HashSet 방식의 선택 기준을 말한다.
