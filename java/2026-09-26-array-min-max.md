# 배열 순회와 최솟값·최댓값

- 날짜: 2026-09-26
- 상태: 오늘의 학습 자료·연습 과제
- 연계 문제: [백준 10818 최소, 최대](https://www.acmicpc.net/problem/10818)

## 1. 순회하면서 필요한 값만 유지하기

최솟값과 최댓값만 필요하다면 모든 입력을 저장하거나 정렬할 필요가 없다.
숫자를 하나 읽을 때마다 현재 값과 비교해 두 변수만 갱신하면 된다.

```java
int minimum = Integer.MAX_VALUE;
int maximum = Integer.MIN_VALUE;

for (int number : numbers) {
    minimum = Math.min(minimum, number);
    maximum = Math.max(maximum, number);
}
```

이 방식은 입력 개수와 관계없이 최솟값·최댓값 변수만 사용한다.

## 2. 초깃값이 중요한 이유

최솟값을 `0`으로 시작하면 모든 입력이 양수일 때 실제 입력에 없는 `0`이
답으로 남을 수 있다. 최댓값도 `0`으로 시작하면 모든 입력이 음수일 때 같은
문제가 생긴다.

안전한 초기화 방법은 두 가지다.

1. 최솟값은 `Integer.MAX_VALUE`, 최댓값은 `Integer.MIN_VALUE`로 둔다.
2. 입력이 비어 있지 않다면 첫 번째 값을 두 변수에 넣고 두 번째 값부터 비교한다.

## 3. 정렬과 한 번의 순회 비교

| 방법 | 시간 복잡도 | 추가 공간 | 적합한 상황 |
| --- | --- | --- | --- |
| 한 번의 순회 | `O(N)` | `O(1)` | 최소·최대만 필요할 때 |
| 정렬 | `O(N log N)` | 구현에 따라 다름 | 전체 순서도 필요할 때 |

문제가 요구하는 결과보다 더 많은 작업을 하지 않는 것이 알고리즘 선택의 핵심이다.

## 4. 배열이 꼭 필요한 경우

입력값을 나중에 다시 사용하거나 정렬·중앙값·구간 계산을 해야 한다면 배열에
저장해야 한다. 반대로 입력을 한 번씩 읽고 집계한 뒤 다시 볼 필요가 없다면
스트리밍 방식으로 처리할 수 있다.

## 핵심 질문

1. 최솟값을 `0`으로 초기화하면 어떤 입력에서 틀릴까?
2. 최솟값과 최댓값만 필요할 때 정렬이 불필요한 이유는 무엇인가?
3. 한 번의 순회 풀이의 시간·공간 복잡도는 무엇인가?
4. 입력을 배열에 저장해야만 하는 상황은 언제인가?

## 직접 해볼 연습

1. `Math.min()` 없이 `if (number < minimum)`으로 구현한다.
2. 숫자 5개의 합계·최솟값·최댓값을 한 번의 순회로 구한다.
3. 모든 값이 음수인 입력으로 초깃값 오류를 재현한다.
4. 백준 10818을 코드를 보지 않고 다시 작성한다.
