# 고정 범위 중복 판별: boolean[]과 Set

> 상태: 오늘의 학습 자료 및 연습 과제

## 핵심 개념

서로 다른 값의 개수를 세려면 각 값을 이미 만났는지 기억해야 한다. 값의 범위가 작고 고정되어 있다면 `boolean[]`, 범위를 모르거나 값이 드문드문 분포한다면 `Set`을 선택할 수 있다.

### boolean[]이 알맞은 경우

- 가능한 값의 범위를 정확히 안다.
- 범위가 메모리에 부담되지 않을 만큼 작다.
- 값 자체를 배열 인덱스로 바꿀 수 있다.

```java
int[] numbers = {1, 3, 3, 7, 1};
boolean[] seen = new boolean[10];
int distinctCount = 0;

for (int number : numbers) {
    if (!seen[number]) {
        seen[number] = true;
        distinctCount++;
    }
}
```

`seen[3] == true`는 숫자 3을 이미 만났다는 뜻이다. 개수는 처음 만난 순간에만 증가시켜야 한다.

### HashSet이 알맞은 경우

```java
Set<Integer> distinct = new HashSet<>();
for (int number : numbers) {
    distinct.add(number);
}
int distinctCount = distinct.size();
```

`HashSet`은 값의 범위를 몰라도 사용할 수 있고 코드가 의도를 잘 드러낸다. 다만 객체와 해시 구조를 사용하므로 작은 고정 범위에서는 배열보다 부가 비용이 크다.

## 선택 기준

| 상황 | 권장 방식 |
|---|---|
| 나머지 0~41처럼 작고 연속적인 범위 | `boolean[]` |
| 문자열, 큰 정수, 범위를 알 수 없는 값 | `HashSet` |
| 값이 매우 넓지만 실제 등장 값은 적음 | `HashSet` |

두 방식 모두 평균적으로 입력을 한 번 순회한다. 배열은 인덱스 접근이 `O(1)`이고, `HashSet`의 삽입도 평균 `O(1)`이다.

## 핵심 질문

1. `seen[number] = true`를 실행할 때마다 개수를 증가시키면 왜 틀릴까?
2. 가능한 값이 `-5`부터 `5`라면 배열 인덱스는 어떻게 변환할까?
3. 학번처럼 범위가 크고 불연속적인 값에는 왜 `HashSet`이 더 적합할까?

## 직접 연습

1. `{2, 2, 5, 7, 5, 9}`의 서로 다른 값 개수를 두 방식으로 구한다.
2. 알파벳 소문자 문자열에서 사용된 문자의 종류 수를 `boolean[26]`으로 센다.
3. 중복 입력만 있는 경우와 모두 다른 경우를 각각 테스트한다.

## 복습 체크

- [ ] 배열 인덱스로 표현할 수 있는 값의 범위를 설명한다.
- [ ] 처음 등장한 값만 세는 조건을 직접 작성한다.
- [ ] 같은 문제를 `HashSet`으로 다시 구현하고 차이를 말한다.
